# AI経理オートメーション (MVP)

Money Forward クラウドのようなオールインワン経理SaaSを見据えた最初のコア機能として、
**経費精算** と **請求書処理(発行・受領)** を1つのシステムに統合し、AIが領収書・請求書を
読み取って勘定科目を判定、信頼度が高ければ人の確認なしで自動仕訳まで行う仕組みを実装しています。
信頼度が低い、または金額が大きい場合は「レビューキュー」に回り、人が確認・修正してから記帳します。

## アーキテクチャ

- **Next.js (App Router) + TypeScript** — フロントエンドとAPI (Route Handlers) を1つのアプリで実装
- **PostgreSQL + Prisma** — 会計データのモデリング(仕訳は必ず貸借複合エントリで保存)
- **Anthropic Claude (Vision + Tool Use)** — 領収書・請求書画像から構造化データを抽出
  - `ANTHROPIC_API_KEY` 未設定時はオフライン動作する `MockAiProvider` に自動フォールバックし、
    APIキーなしでも一連の自動化フローを確認できます (`src/lib/ai/index.ts`)

```
src/lib/ai/            AIプロバイダのインターフェースと実装 (Claude / モック)
src/lib/accounting/    勘定科目マスタ・仕訳自動化エンジン・取引先の名寄せ・総勘定元帳集計
src/app/api/           経費精算・請求書・レビューキュー・ダッシュボード・元帳・試算表のAPI
src/app/               ダッシュボード / 経費精算 / 請求書 / レビューキュー / 総勘定元帳 / 試算表 画面
prisma/schema.prisma   会社・勘定科目・経費・請求書・仕訳・AI抽出結果のデータモデル
```

### 自動化の判断ロジック (`src/lib/accounting/automation.ts`)

1. AIが画像から金額・取引先・勘定科目・信頼度(0〜1)を抽出
2. `AutomationRule` (会社×区分ごとの閾値。初期値: 信頼度0.9以上 かつ 金額が上限以下) と比較
3. 条件を満たせば `JournalEntry` を `AUTO_POSTED` として即記帳
4. 満たさなければ `PENDING_REVIEW` としてレビューキューに積み、人が承認/修正/却下するまで確定させない

これにより「AIが半自動で作業する」を、実際に仕訳を切りながらも人の最終責任を残す形で実現しています。

## デプロイして使う(ローカル環境構築不要)

Node.jsやPostgreSQLをローカルにインストールしなくても、Vercel上にデプロイしてブラウザだけで使えます。

1. https://vercel.com を開き、**GitHubアカウントでサインアップ/ログイン**する
2. ダッシュボードで **「Add New...」→「Project」**
3. このリポジトリ(`wakisenri716-cpu/-`)を **Import** する
4. Import画面で **「Storage」タブ** → **「Create Database」** → **Postgres**(Neon)を選んで作成
   - これで `DATABASE_URL` が自動的にプロジェクトの環境変数に設定されます
5. **「Environment Variables」** に以下を追加:
   - `SEED_SECRET` = 好きな文字列(例: `mysecret123`。他人に推測されにくいものにする)
   - `ANTHROPIC_API_KEY` = 空欄のままでOK(モックAIで動作します)
6. **「Deploy」**を押す(数分待つ)
7. デプロイ完了後に表示されるURL(例: `https://xxxx.vercel.app`)の末尾に
   `/api/seed?secret=手順5で設定した文字列` を付けて**一度だけブラウザで開く**
   - `{"ok":true,...}` と表示されればデータベースの初期化完了
8. あらためてそのURL(`https://xxxx.vercel.app`)を開くと `/login` に飛ぶので、名前とメールアドレスを
   入力してログインすれば使えます

以後は同じURLをブックマークして使えます。データはVercelが作ったPostgreSQL(Neon)に保存され続けます。

## ローカルで動かす場合

```bash
cp .env.example .env   # DATABASE_URL / ANTHROPIC_API_KEY を設定
npm install
npm run db:migrate     # マイグレーション適用
npm run db:seed        # デモ会社・勘定科目・従業員・自動化ルールを投入
npm run dev
```

`ANTHROPIC_API_KEY` を設定しない場合、AI抽出はモック実装(アップロードしたファイルから
決定的に生成した架空データ)になります。実際の画像読み取りを試すには `.env` にキーを設定してください。

起動後、ブラウザで `http://localhost:3000` を開くと `/login` に飛びます。**名前とメールアドレスだけで
入れる仮ログイン**(パスワードなし)なので、自分の名前を入力してログインしてください。同じメールアドレスで
再度ログインすれば同じユーザーとして戻れます。ログインしたユーザーが経費精算の申請者になります。

## 使い方

0. `/login` — 名前・メールアドレスを入力してログイン(仮ログイン、パスワード不要)。
1. `/expenses` — 「新しい経費精算を作成」→ レシート画像をアップロード。AIが自動で科目・金額を判定し、
   信頼度が高ければ即座に仕訳が切られます。
2. `/invoices` — 「受領請求書」「発行請求書」タブを切り替えて画像をアップロード。受領側は買掛金、
   発行側は売掛金・売上として自動仕訳されます。
3. `/review` — 自動処理されなかった項目を確認し、必要なら勘定科目を修正して承認、または却下します。
4. `/` — 自動処理件数・レビュー待ち件数・自動化率と直近の仕訳一覧を確認できます。
5. `/ledger` — 勘定科目ごとの仕訳明細(総勘定元帳)と残高推移を確認できます。
6. `/trial-balance` — 全勘定科目の借方・貸方合計と残高を集計し、貸借が一致しているか確認できます。
7. `/invoices` の各行で残高が残っている請求書に金額を入力し「記録」を押すと、支払・入金が記録され、
   買掛金/売掛金の消込仕訳が自動で切られます。全額消込まれると請求書は「支払・入金済み」になります。
8. `/assets` — 資産名・取得価額・耐用年数を入力して登録すると、取得の仕訳(固定資産/普通預金)が自動記帳。
   月ごとに「◯◯分を計上」ボタンを押すと定額法で計算した減価償却費が仕訳されます(同じ月への二重計上は不可、
   残存価額まで償却すると自動的に打ち止め)。
9. `/vendors` — AI処理で自動登録された取引先・顧客の一覧。取引先名を修正したり、「既定の勘定科目」を
   設定できます。既定科目を設定すると、その取引先からの次回以降の領収書・受領請求書はAIの判定より
   優先してその科目で仕訳されます(誤判定の学習・精度向上に使えます)。
10. `/income-statement` — 収益・費用を集計し、当期純利益を計算します(損益計算書)。確定申告の
    損益計算の土台になります。
11. `/balance-sheet` — 資産・負債・純資産を集計します(貸借対照表)。期末決算(仕訳による振替)は
    行っていないため、純資産には当期純利益をその場で加算して表示し、資産合計 = 負債+純資産合計が
    常に一致するようにしています。

総勘定元帳・試算表・損益計算書・貸借対照表は `AUTO_POSTED`(AI自動記帳)と `POSTED_MANUALLY`(人が承認・修正して記帳)の
仕訳のみを集計し、`PENDING_REVIEW`(レビュー待ち)・`VOID`(却下)は含みません。

いずれのページにも「CSVダウンロード」ボタンがあり、Excelで開ける形式(UTF-8 BOM付き)でエクスポートできます。
税理士への引き継ぎや確定申告準備にそのまま使えます。

## 既知の制約 / 次のステップ

このMVPはスコープを絞っています。将来カテゴリを拡張していく前提で、次を優先的に検討してください。

- **認証は仮実装・マルチテナント未実装**: ログインは名前+メールアドレスのみでパスワード検証なし
  (`src/lib/auth.ts`)。全ユーザーが単一のデモ会社に属する前提 (`src/lib/demo.ts`)。実運用前には
  パスワード/OAuth等の本物の認証、会社切り替え、権限(承認者/経理/従業員)の追加が必要です。
- **ファイル保存が簡易的**: 領収書・請求書画像はDBにdata URIとして保存しています。本番ではS3等の
  オブジェクトストレージに切り出してください。
- **消費税処理は簡略化**: 経費側はインボイス制度の適格請求書区分や軽減税率までは考慮していません。
- **入金・支払は全額/一部を手動記録**: 銀行明細との自動照合(銀行API連携によるAI消込マッチング)は未実装で、
  すべて普通預金(1020)経由という前提です。現金や他口座での決済には対応していません。
- **減価償却は定額法のみ・手動計上**: 定率法や資産の除却・売却には対応していません。月次計上も
  ボタンを押した分だけで、自動で毎月計上されるわけではありません。
- **確定申告書類は未生成**: 損益計算書までで、実際の確定申告書(青色申告決算書など)のフォーマット出力は未対応です。
- **他カテゴリ未着手**: 原価管理、連結会計、電子帳簿保存法対応、新リース会計基準対応は
  今回のスコープ外です(法人会計の基本である総勘定元帳・試算表・損益計算書、債権・債務の入金消込、
  固定資産・減価償却、取引先マスタは実装済み)。
  今回作った `Account` / `JournalEntry` / `AiExtraction` / `AutomationRule` は共通基盤として
  そのまま拡張できる設計にしているので、次はどのカテゴリを優先するか決めて機能を積み増していく想定です。
