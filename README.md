# AI経理オートメーション (MVP)

Money Forward クラウドのようなオールインワン経理SaaSを見据えた最初のコア機能として、
**経費精算** と **請求書処理(発行・受領)** を1つのシステムに統合し、AIが領収書・請求書を
読み取って勘定科目を判定、信頼度が高ければ人の確認なしで自動仕訳まで行う仕組みを実装しています。
信頼度が低い、または金額が大きい場合は「レビューキュー」に回り、人が確認・修正してから記帳します。

## アーキテクチャ

- **Next.js (App Router) + TypeScript** — フロントエンドとAPI (Route Handlers) を1つのアプリで実装
- **PostgreSQL + Prisma** — 会計データのモデリング(仕訳は必ず貸借複合エントリで保存)
- **Anthropic Claude (Vision + Tool Use)** — 領収書・請求書画像から構造化データを抽出
  - `ANTHROPIC_API_KEY` 未設定時はオフライン動作する `MockAiProvider` に自動フォールバックし、
    APIキーなしでも一連の自動化フローを確認できます (`src/lib/ai/index.ts`)
- **UI**: 左サイドバー(業務/帳票でセクション分け、モバイルは上部の横スクロールピルメニューに切り替え)、
  インディゴをブランドカラーにしたTailwind CSSのデザイン(`src/components/Sidebar.tsx`)

```
src/lib/ai/            AIプロバイダのインターフェースと実装 (Claude / モック)
src/lib/accounting/    勘定科目マスタ・仕訳自動化エンジン・取引先の名寄せ・総勘定元帳集計・在庫(移動平均法)
src/app/api/           経費精算・請求書・レビューキュー・ダッシュボード・元帳・試算表のAPI
src/lib/pos/           POSレジ連携 (スマレジAPIクライアント / AirレジCSVパーサ / 日次売上の自動仕訳)
src/app/               ダッシュボード / 経費精算 / 請求書 / レビューキュー / POSレジ連携 / 在庫管理 / 総勘定元帳 / 試算表 画面
prisma/schema.prisma   会社・勘定科目・経費・請求書・仕訳・AI抽出結果のデータモデル
```

### 自動化の判断ロジック (`src/lib/accounting/automation.ts`)

1. AIが画像から金額・取引先・勘定科目・信頼度(0〜1)を抽出
2. `AutomationRule` (会社×区分ごとの閾値。初期値: 信頼度0.9以上 かつ 金額が上限以下) と比較
3. 条件を満たせば `JournalEntry` を `AUTO_POSTED` として即記帳
4. 満たさなければ `PENDING_REVIEW` としてレビューキューに積み、人が承認/修正/却下するまで確定させない

これにより「AIが半自動で作業する」を、実際に仕訳を切りながらも人の最終責任を残す形で実現しています。

## デプロイして使う(ローカル環境構築不要)

Node.jsやPostgreSQLをローカルにインストールしなくても、Vercel上にデプロイしてブラウザだけで使えます。

1. https://vercel.com を開き、**GitHubアカウントでサインアップ/ログイン**する
2. ダッシュボードで **「Add New...」→「Project」**
3. このリポジトリ(`wakisenri716-cpu/-`)を **Import** する
4. Import画面で **「Storage」タブ** → **「Create Database」** → **Postgres**(Neon)を選んで作成
   - これで `DATABASE_URL` が自動的にプロジェクトの環境変数に設定されます
5. **「Environment Variables」** に以下を追加:
   - `SEED_SECRET` = 他人に推測されにくい好きな文字列(`/api/seed` を手動で実行するときだけ使います。省略可)
   - `ANTHROPIC_API_KEY` = 空欄のままでOK(モックAIで動作します)
   - メールを送るなら `SMTP_HOST`・`SMTP_PORT`・`SMTP_USER`・`SMTP_PASS`(Gmail はアプリ パスワード)と、毎朝のお知らせ用の `CRON_SECRET`
     (後からでも追加できます。手順はアプリの「設定 → メール設定・送信履歴」に表示されます)
6. **「Deploy」**を押す(数分待つ)
7. デプロイ完了後に表示されるURL(例: `https://xxxx.vercel.app`)を**すぐに**開くと「最初の管理者を作成」画面が出るので、
   名前・メールアドレス・パスワードを入力する(データベースの初期化もここで自動で行われます)。
   **最初に登録した人が管理者になる**ので、URLを他人に教える前に済ませてください。作成後は誰も「最初の管理者」を作れなくなります
8. ほかのメンバーは、ログイン後の「設定 → ユーザー管理」で追加し、メールアドレスと初期パスワードを本人に伝えます

以後は同じURLをブックマークして使えます。データはVercelが作ったPostgreSQL(Neon)に保存され続けます。

## ローカルで動かす場合

```bash
cp .env.example .env   # DATABASE_URL / ANTHROPIC_API_KEY を設定
npm install
npm run db:migrate     # マイグレーション適用
npm run db:seed        # デモ会社・勘定科目・従業員・自動化ルールを投入
npm run dev
```

`ANTHROPIC_API_KEY` を設定しない場合、AI抽出はモック実装(アップロードしたファイルから
決定的に生成した架空データ)になります。実際の画像読み取りを試すには `.env` にキーを設定してください。

起動後、ブラウザで `http://localhost:3000` を開くと「最初の管理者を作成」画面が出ます。以後はメールアドレスとパスワードでログインします。ログインしたユーザーが経費精算の申請者になります。

### ログインの仕組み(`src/lib/auth/`)

- パスワードは Node 標準の scrypt でハッシュ化して保存し、同じメールアドレスへのログインに5回続けて失敗すると15分間ロックします。
  登録されていないメールアドレスでも同じエラー・同じ処理時間にして、登録の有無を推測されないようにしています。
- ログインするとランダムなセッショントークンを httpOnly クッキーに入れ、DBにはそのハッシュだけを保存します(有効期限30日)。
- `proxy.ts` はクッキーの有無と形だけを見て未ログインの人をログイン画面へ送り、実際の確認はすべての画面・APIが通る
  `requireUser()` / `requireCompanyId()` でDBのセッションと照合します(proxyをすり抜けてもデータには届きません)。
- パスワード変更・再設定・利用停止をすると、その人のほかの端末のログインはすべて解除されます。

### 権限(`src/lib/auth/session.ts`)

| 権限 | 使える画面 |
| --- | --- |
| 管理者 | すべて(ユーザー管理・会社情報を含む) |
| 経理担当 | ユーザー管理・会社情報以外のすべて |
| 従業員 | 経費精算(自分の分だけ)・タイムカード・アカウント |

従業員が他の画面やAPIを開くと経費精算の画面に戻されます。メニューも権限に合わせて表示が変わります
(実際の制限はサーバー側の `requireCompanyId()` / `requireMember()` で行っています)。

## 使い方

0. `/login` — メールアドレスとパスワードでログイン。`/account` で自分のパスワードを変更、管理者は `/users` で
   メンバーの追加・権限変更・パスワード再設定・利用停止ができます。
1. `/expenses` — 「新しい経費精算を作成」→ レシート画像をアップロード。AIが自動で科目・金額を判定し、
   信頼度が高ければ即座に仕訳が切られます。
2. `/invoices` — 「受領請求書」「発行請求書」タブを切り替えて画像をアップロード。受領側は買掛金、
   発行側は売掛金・売上として自動仕訳されます。発行請求書タブの「請求書を作成」からは、品目・数量・単価・税率(10% / 8%)を
   入力して**適格請求書(インボイス)形式の請求書を作成**できます。作成すると「売掛金 / 売上高・仮受消費税」の仕訳を自動で記帳し、
   印刷・PDF保存用の画面を開きます。消費税は税率ごとに合計してから1回だけ端数を切り捨てます(インボイス制度のルール)。
   請求書番号は `INV-年月-連番` で自動採番します。発行元の会社名・登録番号・住所・振込先は `/company`(管理者)で設定します。
3. `/review` — 自動処理されなかった項目を確認し、必要なら勘定科目を修正して承認、または却下します。
4. `/` — 今月の売上・費用・利益(先月比)と現預金の残高、直近12か月の売上・費用・利益のグラフ、
   「やることリスト」(レビュー待ち・銀行明細の確認待ち・期限切れの請求書・退勤の打刻忘れ・先月分の給料の未計上・在庫切れ)、
   自動化率と直近の仕訳一覧を確認できます。
5. `/ledger` — 勘定科目ごとの仕訳明細(総勘定元帳)と残高推移を確認できます。
6. `/trial-balance` — 全勘定科目の借方・貸方合計と残高を集計し、貸借が一致しているか確認できます。
7. `/invoices` の各行で残高が残っている請求書に金額を入力し「記録」を押すと、支払・入金が記録され、
   買掛金/売掛金の消込仕訳が自動で切られます。全額消込まれると請求書は「支払・入金済み」になります。
8. `/assets` — 資産名・取得価額・耐用年数を入力して登録すると、取得の仕訳(固定資産/普通預金)が自動記帳。
   月ごとに「◯◯分を計上」ボタンを押すと定額法で計算した減価償却費が仕訳されます(同じ月への二重計上は不可、
   残存価額まで償却すると自動的に打ち止め)。
9. `/vendors` — AI処理で自動登録された取引先・顧客の一覧。取引先名を修正したり、「既定の勘定科目」を
   設定できます。既定科目を設定すると、その取引先からの次回以降の領収書・受領請求書はAIの判定より
   優先してその科目で仕訳されます(誤判定の学習・精度向上に使えます)。
10. `/income-statement` — 収益・費用を集計し、当期純利益を計算します(損益計算書)。確定申告の
    損益計算の土台になります。
11. `/balance-sheet` — 資産・負債・純資産を集計します(貸借対照表)。期末決算(仕訳による振替)は
    行っていないため、純資産には当期純利益をその場で加算して表示し、資産合計 = 負債+純資産合計が
    常に一致するようにしています。
12. `/pos` — POSレジ(スマレジ・Airレジ)の売上を取り込み、営業日ごとに
    「現金・クレジット売掛金 / 売上高・仮受消費税」の仕訳を自動記帳します。取消取引は除外し、返品(マイナス会計)は
    その日の売上から差し引きます。同じ会計を再度取り込んでも重複しません(取引IDで判定)。

13. `/inventory` — 商品を登録し、入庫(仕入)・出庫・棚卸を記録します。在庫は移動平均法で評価し、
    - 入庫: 商品 / 現金・普通預金・買掛金(消費税10%を仮払消費税として計上するか選択可)
    - 出庫: 売上原価 / 商品(平均単価 × 数量)
    - 棚卸: 実際に数えた数との差を 売上原価 ⇔ 商品 で調整(減っていれば原価、増えていれば原価のマイナス)

    の仕訳を自動記帳します。在庫金額の合計は貸借対照表の「商品」と一致し、在庫一覧はCSVでダウンロードできます
    (棚卸表として税理士に渡せます)。在庫数がマイナスになる出庫はエラーになり、同時に記録してもズレないよう
    商品ごとにロックしています。

14. `/journal` — すべての仕訳を日付順に一覧できる仕訳帳です(月ごとに絞り込み・CSVダウンロード可)。資本金・借入金・
    給料・家賃の振込など、ほかの画面を通らない取引はここから直接入力します。「資本金を入金」「給料を支払」などの
    テンプレートを押すと借方・貸方の科目が入るので、金額を入れるだけで登録できます。借方合計と貸方合計が一致しないと
    登録できません。手入力した仕訳は「取消」で帳簿から外せます(経費・請求書・POS・在庫などの仕訳は元データと
    紐づいているため、ここからは取り消せません)。

15. `/bank` — ネットバンキングからダウンロードした入出金明細のCSVを取り込むと、次の順で自動処理します。
    1. **請求書の消込**: 残高と金額がちょうど一致する請求書が1件だけあれば、入金・支払として消込(入金なら発行請求書、出金なら受領請求書)
    2. **過去の記帳から学習**: 以前に同じ摘要の明細を記帳していれば、その科目を使う(人が直した科目も覚える)
    3. **キーワード**: 「手数料」「家賃」「給与」「利息」「社会保険」「税」などの摘要から科目を判定(半角カナにも対応)
    4. **AI**: それでも決まらない明細は Claude が勘定科目と信頼度を判定(APIキー未設定時は判定せず確認待ちに回す)

    信頼度が自動化ルール(初期値90%)以上なら自動で仕訳し、それ以外は「確認待ち」に残るので、科目を選んで「確定」するか
    「対象外」(自分の口座間の振替など)にします。処理済みの明細は「やり直す」で確認待ちに戻せます(自動の仕訳は取消扱い)。
    日付・摘要・出金・入金(または符号付きの金額1列)・残高の列を名前で探すので、多くの銀行のCSVにそのまま対応し、
    同じ明細を何度取り込んでも二重になりません。

16. `/shifts` — スタッフ(名前・時給)を登録し、週ごとのシフト表で勤務を組みます。「先週のシフトをコピー」で
    毎週の入力を省けます。日付をまたぐ勤務(22:00〜翌5:00 など)にも対応しています。勤務時間と人件費は次の割増を含めて
    自動で計算します(源泉所得税・社会保険料などを差し引く前の総支給額の見込み)。
    - 深夜割増: 22:00〜翌5:00 の勤務は25%増
    - 残業割増: 1日の実働が8時間を超えた分は25%増(深夜と重なれば合計50%増)

    月ごとに「給料として計上」を押すと「給料手当 / 未払金」の仕訳を月末日付で作ります(同じ月は1回だけ。取り消して計上し直し可)。
    計上済みの会社では、銀行明細の給与の振込は「未払金」の支払いとして判定されるので、給料が二重に計上されません。

17. `/timeclock` — お店の共用タブレットなどで開いておくタイムカードです。スタッフが自分の名前を押して「出勤」
    「休憩開始」「休憩終了」「退勤」を記録します(休憩中に退勤すると休憩はそこまでで自動的に締めます)。
    16時間以上出勤中のままの記録は退勤の押し忘れとして扱い、次の出勤は新しい記録として受け付けます。
18. `/attendance` — シフトの予定と打刻の実績を週ごとに並べ、遅刻・早退・打刻なし・退勤の押し忘れを表示します。
    打刻を押して修正、空いた日に追加でき、修正した記録には「修正済み」と表示されます。
    **人件費は、退勤まで打刻された日は実績で、打刻のない日はシフトの予定で計算します**(`/shifts` の月の人件費・給料の計上に反映)。
19. **タイムカードの暗証番号**: `/shifts` のスタッフ一覧で4桁の暗証番号を設定すると、そのスタッフは打刻のたびに
    テンキーで暗証番号を入力します(本人以外が押せなくなります)。5回続けて間違えると5分間打刻できなくなります。
    暗証番号はハッシュ化して保存し、画面やAPIには「設定済みかどうか」しか返しません。未設定のスタッフは今まで通り名前を押すだけです。
20. `/tax` — 期間中の「仮受消費税(売上で預かった消費税)」と「仮払消費税(仕入・経費で支払った消費税)」を
    請求書・POSレジ・在庫などの発生元ごとに集計し、納める(または還付される)消費税の目安を表示します(原則課税での概算。CSV出力可)。
21. `/quotes` — 見積書を作成して印刷・PDF保存できます(番号は `QT-年月-連番`、仕訳は作りません)。受注したら「請求書にする」で、
    同じ宛先・明細の請求書と売上の仕訳を作ります(同じ見積書から2枚できないようにしています)。見積書・請求書とも
    「複製して作成」で、前回と同じ内容から作り始められます(毎月の定額請求などに)。
22. `/monthly` — 売上・費用を勘定科目ごと・月ごとに並べた月次推移表です(期首月から12か月、年度の切り替え・CSV出力可)。
    「予算を設定」で科目ごとの年間予算を入れると、実績が予算の何%かを表示します(費用が予算超過なら赤)。
23. `/receivables` — 売掛金(入金待ち)・買掛金(支払予定)を取引先ごと・請求書ごとに一覧し、期日からの超過日数で
    「期日前 / 1〜30日 / 31〜60日 / 61日以上」に分けます(年齢表。CSV出力可)。
24. `/reimbursements` — 従業員が立て替えた経費(経費精算で記帳済みのもの)を本人に支払ったら「精算する」を押すと、
    「未払金 / 普通預金(または現金)」の仕訳を記帳します。レビュー待ちの明細が残っている経費精算は精算できず、
    精算済みの経費精算には従業員の画面にも「精算済み」と表示され、レシートを追加できなくなります(取消も可)。
25. `/documents` — アップロードした領収書・請求書を取引日(範囲)・金額(範囲)・取引先で組み合わせて検索し、画像を表示できます
    (電子帳簿保存法の検索要件を想定)。
26. `/recurring` — 家賃・リース料・借入金の返済など毎月同じ仕訳を「定期取引」として登録します(記帳日は1〜28日か月末、開始月・終了月つき)。
    記帳日が来るとダッシュボードのやることリストに出て、ボタン1つで記帳できます(過去12か月分までの未記帳分をまとめて記帳可)。
    同じ月の二重記帳はできず、仕訳帳から取り消した月は記帳し直せます。
27. `/journal/import` — 他の会計ソフトやExcelで作った仕訳をCSVで取り込めます(UTF-8 / Shift_JIS)。1行に借方と貸方を1つずつ書き、
    同じ伝票番号の行は複合仕訳にまとめます。科目はコードでも名前でも指定でき、取り込む前に内容を確認できます。
    エラーが1行でもあれば何も取り込まず、同じファイルを2回取り込んでも重複分は飛ばします。
28. `/cashflow` — 今日の現預金に、請求書の入金予定・支払予定(期日ベース)、定期取引、立替経費の精算を足し引きして、
    この先3か月の月末残高を見込みます。残高がマイナスになる月があれば警告します。
29. `/audit` — 操作ログ(管理者のみ)。ログイン、仕訳の入力・取消・CSV取込、請求書・見積書の作成・取消、入金の記録、
    ユーザーやスタッフの変更、給料・減価償却・定期取引の計上などを「誰が・いつ・何を」で記録します(CSV出力可)。
30. **固定資産の除却・売却**: `/assets` の「除却・売却」で、帳簿価額と売却額の差を「固定資産売却益」または
    「固定資産除売却損」として記帳し、資産を帳簿から外します。当月分の減価償却は「まとめて計上する」で全資産に一括計上できます。
31. `/closing` — 締め処理。決算が終わった日までの帳簿を「締める」と、その日以前の日付の仕訳は**どの画面・処理からも**追加・変更・取消
    できなくなります(PostgreSQL のトリガーで `JournalEntry` / `JournalLine` への書き込みを拒否し、アプリでは日本語のエラーに変換)。
    レビュー待ち・確認待ちが残る期間は締められません。締め・解除は管理者だけができ、操作ログに残ります。
32. `/accounts` — 勘定科目の追加・名前の変更・非表示。区分は科目コードの先頭(1 資産 / 2 負債 / 3 純資産 / 4 収益 / 5〜9 費用)で決まり、
    非表示の科目は入力画面の選択肢から消えます(過去の仕訳・帳票には残る)。
33. `/backup` — 会社の全データ(仕訳帳・請求書・経費・固定資産・在庫・勤怠・銀行明細・操作ログなど)を CSV にして ZIP でダウンロード
    (管理者のみ。画像は含まない)。仕訳帳.csv は「仕訳のCSV取込」と同じ形式です。
34. **取引先・顧客ごとの取引履歴**: `/vendors` の「取引の履歴」から、請求書・見積書・経費と、入金待ち・支払予定の残高を確認できます。
35. **督促状**: 期日を過ぎた発行請求書は、`/receivables` や請求書の画面から「お支払いについてのご確認(お願い)」を作って印刷・PDF保存できます。
36. **在庫の発注点**: `/inventory` で商品ごとに発注点を設定すると、在庫がその数以下になったときにダッシュボードのやることリストに出ます。
37. **2段階認証**: `/account` で認証アプリ(Google Authenticator など)を設定すると、ログインのときにパスワードに加えて6桁のコードが必要になります
    (RFC 6238 の TOTP を Node 標準の crypto で実装。前後30秒まで許容し、同じコードの再利用は拒否)。設定時に回復コードを8個発行し(ハッシュのみ保存)、
    スマホをなくしたときは回復コードでログインできます。確認コードの失敗もパスワードと同じく5回でロックされ、管理者は `/users` から本人の2段階認証を解除できます。
38. **ログイン中の端末**: `/account` で自分がログインしている端末(ブラウザ・OS・最終利用日時)を確認し、1台ずつ、またはこの端末以外をまとめてログアウトできます。
39. **仕訳の検索**: `/journal` で摘要・メモのキーワード、勘定科目、金額(明細1行の金額)の範囲、種類を組み合わせて検索でき、CSVも検索結果で出力されます。
40. **損益計算書の前年比較**: 期間を決めて表示すると、前年同期の金額・増減・増減率を並べます(CSVにも出力)。
41. `/recurring-invoices` — 定期請求。作成済みの請求書をひな形にして、毎月決まった日(1〜28日か月末)に同じ宛先・明細の請求書と売上の仕訳を作ります
    (支払期限は翌月末か請求日から◯日後)。請求日が来るとダッシュボードに出て、ボタン1つで作成できます。同じ月は1枚だけで、取り消した月は作り直せます。
42. **ダッシュボードのランキング**: 今期の顧客別売上と、費用の科目別内訳の上位5件を表示します。
43. **給与明細**: `/shifts` の月の人件費の「明細」から、スタッフごとの給与明細書(勤怠・支給の内訳、日ごとの勤務)を印刷・PDF保存できます(控除は含まない総支給額)。
44. **納品書・領収書**: 作成した請求書の画面から、同じ明細の納品書と、全額入金済みの請求書の領収書(税率ごとの内訳・登録番号つき、但し書きは変更可)を発行できます。
45. `/departments` — 部門別損益。店舗・事業部などの部門を登録し、仕訳帳・請求書の作成時に選ぶか、仕訳帳の一覧で後から付けると、
    期間を指定して部門ごとの売上・費用・利益を並べます(CSV出力可)。仕訳のCSV取込でも「部門」列で指定できます。
46. **はじめにやること**: 管理者のダッシュボードに、会社情報・2段階認証・メンバー招待・レシート・請求書・銀行明細・バックアップの7つの設定状況を表示します。
47. **ホーム画面に追加(PWA)**: スマホ・タブレットのブラウザで「ホーム画面に追加」すると、アプリのように全画面で開けます(タイムカードの共用端末などに)。
48. **CSVで一括登録**: `/vendors` で取引先・顧客(既定の勘定科目つき)、`/inventory` で商品(コード・単位・発注点)をCSVからまとめて登録できます。
49. **経費精算の承認フロー**: `/company` で「申請 → 承認してから精算する」をオンにすると、従業員は `/expenses` でレシートをそろえて「申請」し、
    管理者・経理担当が `/reimbursements` で「承認」か理由つきの「差戻し」をします。承認されるまで精算(支払)はできず、申請中はレシートを追加できません。
    承認待ちの件数はダッシュボードの「やること」に出ます。
50. **消費税の計算方式**: `/tax` で原則課税・簡易課税(事業区分 第1〜6種のみなし仕入率)・2割特例の納付見込みを並べて比べられ、
    管理者は使う方式を設定できます(CSVにも3方式の金額を出力)。
51. `/analysis` — 経営分析。売上総利益率・営業利益率・人件費率・流動比率・当座比率・自己資本比率・手元資金(月商の何か月分)・売掛金の回収日数を
    前年同期と比べ、それぞれの意味と目安を表示します。
52. **帳票の印刷・PDF保存**: 試算表・損益計算書・貸借対照表・月次推移・部門別損益・消費税集計・売掛金/買掛金・総勘定元帳に「印刷・PDF」ボタンを追加。
    メニューやボタンを除いた帳票だけを印刷します。
53. **仕訳のひな形・複製**: 仕訳帳で入力中の仕訳を「ひな形として保存」すると(金額・メモも保存)、次からボタン1つで呼び出せます。
    一覧の「複製」で、過去の仕訳と同じ内容を入力欄に入れられます。
54. **総勘定元帳の残高グラフ**: 科目を選ぶと、日ごとの残高の推移を線グラフで表示します(指でなぞる・マウスを乗せると日付と残高を表示)。
55. `/files` — 書類フォルダ。契約書・PDF・写真・Excelなどの書類を、フォルダ(中にフォルダも作れる、10階層まで)に分けて保存できます。
    ボタンかドラッグでまとめて追加(1ファイル4MBまで)、名前変更・移動・メモ・ファイル名とメモでの検索ができます。
    PDFと画像はその場で表示・印刷でき、それ以外はダウンロードして開きます(管理者・経理担当のみ。フォルダは空のときだけ削除可)。
56. **書類の印刷**: 請求書・見積書・経費精算・立替経費の精算・銀行明細・定期取引・資金繰り・固定資産・勤怠・取引先・仕訳帳・在庫・証憑・操作ログの各画面に
    「印刷・PDF」ボタンを追加(入力欄やボタンは印刷しない)。経費精算は「精算書を印刷」で、明細・合計・承認欄・レシート画像つきの経費精算書を出せます(従業員も自分の分を印刷可)。
57. `/financial-statements` — 決算報告書。年度を選ぶと、表紙・貸借対照表(流動/固定の区分つき)・損益計算書(売上総利益〜経常利益〜当期純利益)・
    販売費及び一般管理費内訳書をまとめて印刷(PDF保存)できます。期の途中は今日までの数字で作ります。
58. `/calendar` — 入金・支払カレンダー。請求書の入金予定・支払予定(未回収・未払いの残り)、定期取引・定期請求の日、書類の期限を月ごとに表示します。
    今月の画面では期日を過ぎた入金・支払を今日の欄に出し、期限切れの入金は督促状の画面へ移動できます。
59. **書類の期限**: 書類フォルダのファイルに期限(契約の満了日など)を設定すると、30日前からダッシュボードの「やること」と書類フォルダのいちばん上に表示します。
60. **証憑をフォルダに保存**: 証憑の検索で、領収書・受け取った請求書の画像を「日付_取引先_金額円」の名前で書類フォルダにコピーできます。
61. **経費1件あたりの上限**: `/company` で上限額を決めると、超えたレシートを経費精算・立替経費の精算・経費精算書に「上限超え」と表示します(精算は止めません)。
62. **メール送信**(`/email` で設定・送信履歴): 請求書・見積書・督促を、画面の「メールで送る」から送れます。本文には、受け取った人がログインせずに
    書類を見て印刷・PDF保存できる共有リンク(推測できない長い文字列)が入ります。宛先は顧客ごとに覚え、送った請求書は「送付済み」になります。
    Gmail(アプリ パスワード)・Resend に対応し、未設定の間はテストモード(送らずに履歴へ記録)。1社1日200通まで。
63. **パスワードを忘れたとき**: ログイン画面の「パスワードを忘れた方」から、再設定のリンク(1時間・1回だけ有効)をメールで受け取れます。
    再設定するとほかの端末のログインはすべて解除されます(2段階認証はそのまま)。リンクは送信履歴にも残しません。
64. **毎朝のやること通知**: `/email` でオンにすると、毎朝8時ごろ(Vercel Cron)、レビュー待ち・期限切れの請求書などがあるときに管理者へメールで知らせます(`CRON_SECRET` が必要)。
65. `/payroll` — 給与計算。シフト・打刻から出した給与に、社会保険料(健康保険・介護保険・厚生年金)・雇用保険料・源泉所得税・住民税の控除をかけて差引支給額を出します。
    スタッフごとに税額表(甲欄/乙欄)・扶養人数・保険の加入・標準報酬月額・通勤手当(非課税)・住民税を設定でき、保険料率は都道府県・年度に合わせて管理者が直せます。
    源泉所得税は国税庁の電子計算機用の計算式(令和8年分)による目安で、税額表と違うときや乙欄(8.8万円以上)は手で直せます。
    計上すると「給料手当・旅費交通費(通勤手当)・法定福利費(会社負担) / 預り金(控除分)・未払金(手取り+会社負担)」の仕訳を作り、
    計算結果を保存します(あとで設定を変えても計上済みの明細は変わりません)。給与明細書にも控除と差引支給額が入ります。
66. **請求書の訂正**: 作成した請求書の「訂正する」から、内容を直した訂正版(番号は元の番号に -R1・-R2 …)を発行できます。
    元の請求書は取消(売上の仕訳も取消)になり、入金の記録・見積書・定期請求・お客さまに送った共有リンクは訂正版に引き継ぎます。
    訂正版には「〇年〇月〇日付 請求書(No.…)を訂正したもの」と訂正の理由を記載し(インボイス制度の修正した適格請求書)、メールも訂正版として送れます。

### POSレジ連携の設定

- **スマレジ(API連携)**: [スマレジ・デベロッパーズ](https://developers.smaregi.dev/)でアプリを作成し、
  「取引(pos.transactions:read)」の権限を付けて、契約ID・クライアントID・クライアントシークレットを
  環境変数 `SMAREGI_CONTRACT_ID` / `SMAREGI_CLIENT_ID` / `SMAREGI_CLIENT_SECRET` に設定します
  (サンドボックスで試す場合は `SMAREGI_SANDBOX=true`)。Vercelなら「Settings → Environment Variables」に追加して再デプロイ。
  未設定の間は、動作確認用のデモ取引(仕訳の摘要に「[デモ]」と付きます)で同期します。
- **Airレジ(CSV取込)**: Airレジの「データ連携API」はAirレジが承認した連携先システム(freee・弥生など)にしか
  公開されていないため、バックオフィスの「日別売上」→「CSVデータをダウンロードする」→「会計明細」で出力した
  CSVをアップロードして取り込みます。列はヘッダー名(取引No・会計日・会計時間・合計・内消費税・現金など)で
  判定するので、出力項目の並び順を変えていても読み込めます。

総勘定元帳・試算表・損益計算書・貸借対照表は `AUTO_POSTED`(AI自動記帳)と `POSTED_MANUALLY`(人が承認・修正して記帳)の
仕訳のみを集計し、`PENDING_REVIEW`(レビュー待ち)・`VOID`(却下)は含みません。

損益計算書・消費税集計は「今期・前期・今月・先月・すべて・日付指定」で期間を、試算表・貸借対照表は「いつ時点か」を
選べます(期首月は会社の決算期の設定に従い、初期値は4月)。

いずれのページにも「CSVダウンロード」ボタンがあり、Excelで開ける形式(UTF-8 BOM付き)でエクスポートできます。
税理士への引き継ぎや確定申告準備にそのまま使えます。

## 既知の制約 / 次のステップ

このMVPはスコープを絞っています。将来カテゴリを拡張していく前提で、次を優先的に検討してください。

- **マルチテナント未実装**: 全ユーザーが1つの会社に属する前提です。権限は管理者・経理担当・従業員の3段階です。
  メール送信を設定していない間は、パスワードを忘れたときは管理者が再設定します。
- **メールに書類は添付しない**: 請求書・見積書はPDFを添付せず、共有リンクで送ります(リンクを知っている人は誰でも見られるので、転送には注意)。
- **ファイル保存が簡易的**: 領収書・請求書画像と書類フォルダのファイルはDBに保存しています。量が増えたらS3等の
  オブジェクトストレージに切り出してください(書類フォルダは1ファイル4MBまで。バックアップにはファイルの一覧だけが入ります)。
- **消費税処理は簡略化**: 経費側はインボイス制度の適格請求書区分や軽減税率までは考慮していません。
  消費税集計は原則課税・簡易課税(事業区分は1つ)・2割特例での目安で、中間納付や消費税申告書の作成には対応していません。
- **電子帳簿保存法は検索のみ**: タイムスタンプの付与や訂正・削除の履歴の保存(真実性の要件)には対応していません。
  事務処理規程を備え付けるなど、運用での対応が必要です。
- **銀行明細はCSV取込・普通預金1口座のみ**: 銀行APIとの直接連携は未実装で、すべて普通預金(1020)の明細として扱います。
  請求書の消込は「残高と金額が完全一致する請求書が1件だけ」の場合に限ります(振込手数料を差し引かれた入金などは確認待ちになります)。
- **減価償却は定額法のみ・手動計上**: 定率法には対応していません。月次計上はボタンを押した分だけで、自動で毎月計上されるわけではありません。
  資産の売却時の消費税(仮受消費税)は計上しません。
- **確定申告書類は未生成**: 損益計算書までで、実際の確定申告書(青色申告決算書など)のフォーマット出力は未対応です。
- **POS連携は日次売上の仕訳まで**: 商品・部門別の売上内訳や、クレジット売掛金の入金消込(カード会社からの
  入金との照合)は未対応です。スマレジの同期は画面から手動で実行します(定期自動同期は未実装)。
- **在庫はPOS売上と未連動**: POSの売上から商品ごとの在庫を自動で減らす連携(商品マスタの紐づけ)は未実装です。
  売れた分は「出庫」か月末の「棚卸」で反映してください。評価方法は移動平均法のみ(先入先出法などは未対応)。
- **給与計算は目安**: 週40時間超の残業・休日出勤の割増、賞与、年末調整・源泉徴収票、算定基礎届・月額変更届(標準報酬月額の決定)は未対応です。
  源泉所得税・保険料は目安なので、税額表・協会けんぽの料率表で確認してください。時給を変更すると、まだ計上していない月は新しい時給で再計算されます。
- **タイムカードの本人確認は暗証番号のみ**: 暗証番号を設定していないスタッフは、ログインした端末で誰でも押せます。
  顔写真の記録や位置情報での確認は未実装です。
- **他カテゴリ未着手**: 原価管理、連結会計、電子帳簿保存法対応、新リース会計基準対応は
  今回のスコープ外です(法人会計の基本である総勘定元帳・試算表・損益計算書、債権・債務の入金消込、
  固定資産・減価償却、取引先マスタは実装済み)。
  今回作った `Account` / `JournalEntry` / `AiExtraction` / `AutomationRule` は共通基盤として
  そのまま拡張できる設計にしているので、次はどのカテゴリを優先するか決めて機能を積み増していく想定です。
