# AI経理オートメーション (MVP)

Money Forward クラウドのようなオールインワン経理SaaSを見据えた最初のコア機能として、
**経費精算** と **請求書処理(発行・受領)** を1つのシステムに統合し、AIが領収書・請求書を
読み取って勘定科目を判定、信頼度が高ければ人の確認なしで自動仕訳まで行う仕組みを実装しています。
信頼度が低い、または金額が大きい場合は「レビューキュー」に回り、人が確認・修正してから記帳します。

## アーキテクチャ

- **Next.js (App Router) + TypeScript** — フロントエンドとAPI (Route Handlers) を1つのアプリで実装
- **PostgreSQL + Prisma** — 会計データのモデリング(仕訳は必ず貸借複合エントリで保存)
- **Anthropic Claude (Vision + Tool Use)** — 領収書・請求書画像から構造化データを抽出
  - `ANTHROPIC_API_KEY` 未設定時はオフライン動作する `MockAiProvider` に自動フォールバックし、
    APIキーなしでも一連の自動化フローを確認できます (`src/lib/ai/index.ts`)

```
src/lib/ai/            AIプロバイダのインターフェースと実装 (Claude / モック)
src/lib/accounting/    勘定科目マスタ・仕訳自動化エンジン・取引先の名寄せ・総勘定元帳集計
src/app/api/           経費精算・請求書・レビューキュー・ダッシュボード・元帳・試算表のAPI
src/app/               ダッシュボード / 経費精算 / 請求書 / レビューキュー / 総勘定元帳 / 試算表 画面
prisma/schema.prisma   会社・勘定科目・経費・請求書・仕訳・AI抽出結果のデータモデル
```

### 自動化の判断ロジック (`src/lib/accounting/automation.ts`)

1. AIが画像から金額・取引先・勘定科目・信頼度(0〜1)を抽出
2. `AutomationRule` (会社×区分ごとの閾値。初期値: 信頼度0.9以上 かつ 金額が上限以下) と比較
3. 条件を満たせば `JournalEntry` を `AUTO_POSTED` として即記帳
4. 満たさなければ `PENDING_REVIEW` としてレビューキューに積み、人が承認/修正/却下するまで確定させない

これにより「AIが半自動で作業する」を、実際に仕訳を切りながらも人の最終責任を残す形で実現しています。

## セットアップ

```bash
cp .env.example .env   # DATABASE_URL / ANTHROPIC_API_KEY を設定
npm install
npm run db:migrate     # マイグレーション適用
npm run db:seed        # デモ会社・勘定科目・従業員・自動化ルールを投入
npm run dev
```

`ANTHROPIC_API_KEY` を設定しない場合、AI抽出はモック実装(アップロードしたファイルから
決定的に生成した架空データ)になります。実際の画像読み取りを試すには `.env` にキーを設定してください。

## 使い方

1. `/expenses` — 「新しい経費精算を作成」→ レシート画像をアップロード。AIが自動で科目・金額を判定し、
   信頼度が高ければ即座に仕訳が切られます。
2. `/invoices` — 「受領請求書」「発行請求書」タブを切り替えて画像をアップロード。受領側は買掛金、
   発行側は売掛金・売上として自動仕訳されます。
3. `/review` — 自動処理されなかった項目を確認し、必要なら勘定科目を修正して承認、または却下します。
4. `/` — 自動処理件数・レビュー待ち件数・自動化率と直近の仕訳一覧を確認できます。
5. `/ledger` — 勘定科目ごとの仕訳明細(総勘定元帳)と残高推移を確認できます。
6. `/trial-balance` — 全勘定科目の借方・貸方合計と残高を集計し、貸借が一致しているか確認できます。

総勘定元帳・試算表は `AUTO_POSTED`(AI自動記帳)と `POSTED_MANUALLY`(人が承認・修正して記帳)の
仕訳のみを集計し、`PENDING_REVIEW`(レビュー待ち)・`VOID`(却下)は含みません。

## 既知の制約 / 次のステップ

このMVPはスコープを絞っています。将来カテゴリを拡張していく前提で、次を優先的に検討してください。

- **認証・マルチテナント未実装**: 現状は seed で作った単一のデモ会社/従業員に固定 (`src/lib/demo.ts`)。
  実運用前にログイン・会社切り替え・権限(承認者/経理/従業員)を追加する必要があります。
- **ファイル保存が簡易的**: 領収書・請求書画像はDBにdata URIとして保存しています。本番ではS3等の
  オブジェクトストレージに切り出してください。
- **消費税処理は簡略化**: 経費側はインボイス制度の適格請求書区分や軽減税率までは考慮していません。
- **他カテゴリ未着手**: 確定申告、債権・債務の入金消込、固定資産・減価償却、原価管理、連結会計、
  電子帳簿保存法対応、新リース会計基準対応は今回のスコープ外です(法人会計の基本である総勘定元帳・試算表は実装済み)。
  今回作った `Account` / `JournalEntry` / `AiExtraction` / `AutomationRule` は共通基盤として
  そのまま拡張できる設計にしているので、次はどのカテゴリを優先するか決めて機能を積み増していく想定です。
